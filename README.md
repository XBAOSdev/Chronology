# 大事年表（Chronology）

> 一款**纯前端、离线可用**的历史时间轴工具。零第三方依赖，双击 `index.html` 即可运行。

面向高中历史学习与教学场景，提供中国史、世界史两套内置时间轴（共 **314** 条史实，覆盖人教版高中历史教科书必修与选择性必修主干内容），支持缩放、折叠、聚合、检索、编辑与导入导出。

---

## 一、快速开始

### 方式 A：双击打开（推荐，完全离线）

直接双击项目根目录的 `index.html`，用 Chrome / Edge / Firefox 等现代浏览器打开即可。

> 项目刻意采用**普通 `<script>` 顺序加载 + 全局变量注册**的方式组织代码与数据，而非 ES Module + `fetch`，正是为了绕过浏览器在 `file://` 协议下对本地文件读取的限制，从而保证双击即可用。

### 方式 B：本地静态服务器

```bash
# 任选其一，在项目根目录执行
python -m http.server 8080
# 或
npx serve .
```

然后访问 `http://localhost:8080/`。

### 方式 C：静态托管（Cloudflare Pages 等）

本项目为**无构建的纯静态站点**，无需任何打包步骤：

1. 将整个目录推送到 Git 仓库，或在 Cloudflare Pages 中直接上传该目录；
2. 构建命令留空，输出目录设为根目录 `.`；
3. 完成部署即可访问。

因所有资源均为相对路径且不含服务端路由，GitHub Pages、Netlify、对象存储静态网站托管等同样适用。

## 五、时间坐标模型（全项目唯一真源）

所有时间→屏幕坐标的换算统一由 `src/core/time-model.js` 提供：

| 真实时间 | 坐标 `x` |
| --- | --- |
| 公元 1 年 | `0` |
| 公元 n 年 | `n - 1` |
| 公元前 n 年 | `-n` |

月 / 日 / 时 / 分作为「年内小数」叠加在年份之上：

- 月：`+ (month - 1) / 12`
- 日：`+ (day - 1) / 365.25`
- 时：`+ hour / 8766`
- 分：`+ minute / 525960`

> 设计要点：公元 1 年与公元前 1 年连续（无「公元 0 年」断层）；公元前年份的小数部分**向公元元年方向递进**。

横向缩放与折叠分别作用于两个独立维度：

```
pxPerYear = BASE_PX_PER_YEAR(2) × zoom × fold
```

- `zoom` 同时影响横纵比例；`fold` **只压缩时间轴横向密度**，节点大小与文字保持不变。

## 六、数据格式

### 6.1 文件形态

单文件 = 单时间轴，JSON 格式，含 `schemaVersion`（当前为 `1`）。

```json
{
  "schemaVersion": 1,
  "id": "user-china-history-1726xxxxxxx",
  "title": "中国史（我的副本）",
  "subtitle": "中华文明发展脉络",
  "category": "中国史",
  "color": "#e0625a",
  "description": "……",
  "source": "user",
  "copyOf": "china-history",
  "exportedAt": "2026-09-10T02:26:32.000Z",
  "events": [
    {
      "id": "cn-1949",
      "timelineId": "user-china-history-1726xxxxxxx",
      "title": "中华人民共和国成立",
      "summary": "开国大典在北京天安门广场举行，中华人民共和国中央人民政府成立。",
      "date": {
        "year": 1949,
        "month": 10,
        "day": 1,
        "precision": "day",
        "display": "1949年10月1日",
        "circa": false
      },
      "level": 1,
      "tags": ["建国"],
      "region": "北京",
      "viewpoint": "",
      "sharedEventId": null,
      "links": []
    }
  ]
}
```

### 6.2 关键字段说明

| 字段 | 说明 |
| --- | --- |
| `precision` | 精度枚举：`century` / `decade` / `year` / `month` / `day` / `hour` / `minute` / `circa` / `range` |
| `date.year` | 整数年份，公元前为负数（如公元前 221 年 → `-221`） |
| `date.display` | 面向展示的文本（如「约公元前 2070 年」），缺省时自动生成 |
| `date.circa` | 是否为约数（「约」） |
| `level` | 事件等级 `1—5`，1 级为最核心 |
| `summary` | 事件描述，**上限 150 字**，超出自动截断 |
| `sharedEventId` | 跨时间轴共享标识（如二战在中/外时间轴共用 `wwii`） |
| `links` | 预留的外部关联字段，当前导出为空数组 |

### 6.3 校验与容错规则

- 缺少 `id` 或 `title` 的时间轴：拒绝导入并提示；
- 事件缺少 `title`：跳过该条并计入警告；
- 事件 `id` 重复：自动重新生成；
- 描述超 150 字：自动截断并提示；
- 单时间轴事件数超过 3000：仅保留前 3000 条并提示；
- 文件 `schemaVersion` 高于程序：按当前规范读取并提示；
- 兼容被 `{ "timeline": { ... } }` 包裹的导出文件。

## 七、编辑与导入导出规则

1. **系统内置时间轴只读**：对其执行任何编辑时，自动另存为一份用户副本（`user-原ID-时间戳`），原始内置数据不受影响。
2. **用户数据在内存中编辑**：所有改动先落在内存，**手动导出**后才会持久化为文件；页面关闭前若存在未导出的改动，会弹出提醒。
3. **导入冲突默认跳过**：当导入的时间轴 `id` 已存在时，默认跳过该条，不覆盖已有数据。
4. **导出**：单条时间轴导出为 `.json`；多条导出为 `.zip`。
5. **ZIP 实现**：零依赖、**store 模式（不压缩）**，自实现本地文件头、中央目录与 CRC32 校验，可在任意解压工具中正常打开。
